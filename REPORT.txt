1. INTRODUCTION
--------------------------------------------------------------------
This project implements a complete CI/CD pipeline for a small AI 
application. The goal is to ensure that every change to the bot is 
automatically tested, evaluated for correctness, and validated against 
a groundedness threshold before being accepted. The pipeline enforces 
quality, prevents regressions, and demonstrates DevOps principles such 
as automation, least privilege, and continuous verification.

The application consists of a simple question‑answering bot with fixed 
responses for school safety procedures. The pipeline evaluates the bot 
using deterministic unit tests and a similarity‑based eval gate.

3. BOT IMPLEMENTATION (src/bot.py)
--------------------------------------------------------------------
The bot provides deterministic responses for three required questions:

- Lockdown procedure  
- Fire drill procedure  
- Late policy  

These responses are intentionally simple and fully grounded in the eval 
dataset. The bot is designed to be predictable so that unit tests and 
eval scoring remain stable.


4. UNIT TESTS (tests/test_bot.py)
--------------------------------------------------------------------
The test suite verifies that the bot returns the exact expected strings 
for each question. These tests ensure that basic regressions are caught 
before the eval gate runs.

Tests include:
- test_lockdown()
- test_fire_drill()
- test_late_policy()


5. EVAL DATASET (tests/eval_cases.json)
--------------------------------------------------------------------
The eval dataset contains multiple cases. Each case includes:
- A question
- The expected grounded answer

The dataset ensures that the bot’s responses remain consistent and 
aligned with the expected safety procedures.


6. EVAL GATE (tests/judge.py)
--------------------------------------------------------------------
The eval gate enforces a groundedness threshold of 0.85. It performs 
the following steps:

1. Loads all eval cases  
2. Computes similarity scores between the bot’s answer and the expected answer  
3. Averages the scores  
4. Fails the build if the average score is below 0.85  

This mechanism prevents hallucinations and ensures safe, predictable 
behavior from the bot.


7. CI/CD PIPELINE (.github/workflows/ci.yml)
--------------------------------------------------------------------
The CI/CD pipeline runs on pushes to both main and regression branches. 
It uses least‑privilege permissions:

permissions:
  contents: read

The pipeline includes the following steps:
1. Checkout code  
2. Set up Python  
3. Install dependencies  
4. Lint  
5. Unit tests  
6. Secret scan  
7. Eval gate  

This ensures that any regression or incorrect bot answer is detected 
before merging.
